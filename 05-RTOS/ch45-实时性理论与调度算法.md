## 45.1 基础概念：实时 ≠ 快

| 术语 | 定义 | 例子 |
|------|------|------|
| 硬实时 Hard RT | 超时=系统失败 | 安全气囊点火、电机 FOC 电流环 |
| 软实时 Soft RT | 偶尔超时可容忍但统计要达标 | 音频播放、UI 刷新 |
| 周期任务 (C,T,D) | 计算耗时 C / 周期 T / 相对截止期 D | ADC 采样 C=0.2ms,T=1ms,D=1ms |
| Jitter 抖动 | 实际触发时刻相对理想值的偏差分布 | PWM 相位抖动 ±2µs |

## 45.2 关键理论：RMS 判定公式的推导与用法

规则：**周期越短优先级越高**（静态优先级，Rate Monotonic Scheduling）；Liu & Layland 1973 证明其在固定优先级调度中最优。可调度充分条件（n 个独立周期任务，D=T 假设）：

```text
U = Σ Ci/Ti ≤ n·(2^(1/n) − 1)
    n=1→1.000   n=2→2(√2−1)=0.828   n=3→0.779   n→∞→ln2≈0.693
含义：U < 69% 时任意周期任务集必然可调度；
      超阈值 ≠ 不可行——充分条件只是「数学不敢担保」，
      必须时间轴仿真验证真实可行性（风险自负）。
例：  C/T={0.5/1, 1/4, 2/10} → U=0.5+0.25+0.2=0.95 > 0.779
      充分条件失败 → 纸笔或脚本仿真时间轴定夺。
```

## 45.3 EDF 对比：动态优先级的诱惑与陷阱

EDF（Earliest Deadline First）：**截止期最近的先跑**，利用率理论上可达 100%，但每次决策都要比较 deadline，且**过载时雪崩式劣化**（多米诺连锁）。RMS 过载只牺牲低优先级任务——**可预测性上静态优先级占优，这正是 FreeRTOS 只提供抢占式固定优先级的根本原因**。落地参照：Zephyr 提供 EDF 调度器选项；Linux 的 `SCHED_DEADLINE` 即 EDF 变体（A 核混合关键性场景）。

## 45.4 优先级翻转三幕剧（火星探路者号同款 Bug）

```text
设定： 低优先级 L 持有互斥锁 M；高 H 等 M；中 M 不需要 M 但优先级居中
第一幕：L 拿锁运行 → 第二幕：H 抢占 L 后阻塞在 M 上 → 第三幕：
        M(中) 就绪并抢占了还在持锁的 L！
        → H 被中优先级间接压制 = 无界阻塞 ★这就是翻转(inversion)
```

1997 年火星探路者号在 VxWorks 上正是此模式：低优气象任务持锁、高优总线管理任务等锁、中优任务反复抢占持锁者，最终触发看门狗复位——地面团队远程开启追踪定位后，打补丁启用优先级继承才修复。两种修复方案：

| 方案 | 机制 | 特点 |
|------|------|------|
| ① 优先级继承 PI | H 等待期间临时提升 L 到 H 级别，让 L 尽快放锁 | FreeRTOS `xSemaphoreCreateMutex()` 自带；`xSemaphoreCreateRecursiveMutex` **不带** |
| ② 优先级天花板 PC | 拿锁瞬间直接升到「所有可能争用者的最高级」 | 阻塞上限确定化=一次临界区时长；OSI/安全认证需自行实现或选 SAFERTOS/AUTOSAR OS |

## 45.5 jitter 解剖表：一条延迟的全链路账单

| 环节 | 典型量级(F407) | 元凶与对策 |
|------|----------------|------------|
| 定时器到中断触发 | <1µs | 硬件固有 |
| NVIC 排队等待 | 0~最长同级 ISR | **主要来源①：缩短高优 ISR** |
| RTOS 抖动(vTaskDelayUntil 精度) | ±2~10µs | tick 分辨率+临界区；tickless 需补偿 |
| 被更高优抢占的累计 | 不确定 | **主要来源②：WCET 预算表管理** |
| Cache miss(M7) | +几十~百 ns/次 | 热代码锁 I-Cache 或放 TCM |

## 45.6 关键代码：任务集可行性体检脚本

```python
tasks = [("adc", 0.5, 1.0), ("ctrl", 1.0, 4.0), ("log", 2.0, 10.0)]  # (name,C,T)
n, U = len(tasks), sum(c/t for _, c, t in tasks)
bound = n * (2**(1/n) - 1)
print(f"U={U:.3f} bound({n})={bound:.3f}",
      "PASS" if U <= bound else "FAIL -> 需时间轴仿真")
```

## 45.7 参数调试技巧

| 症状 | 测量手段 | 调什么 | 判据 |
|------|----------|--------|------|
| 中断响应偶发变长 | 外部信号+ISR 翻转脚，LA 统计千次 | 缩短高优 ISR、压缩关中断区 | P99 < 10µs @168MHz |
| 任务唤醒抖动大 | vTaskDelayUntil 周期任务打点 DWT | 提高 tick 分辨率、砍同步日志 | jitter P99 < 5µs |
| 最坏阻塞不可控 | ftrace irqsoff（MCU 用 BASEPRI 包裹计时） | 拆长临界区、重排优先级 | < 最紧 deadline 的 10% |

## 45.8 实测数据表：同一控制环在不同配置下的 jitter（10kHz PWM 相位法）

| 系统配置 | P99 jitter | max |
|----------|------------|-----|
| 裸机 TIM 中断直接执行 | 0.3µs | 0.5µs |
| FreeRTOS 任务+vTaskDelayUntil | 1.8µs | 6µs |
| +串口日志同步打印 | 4.5µs | **87µs(!)** |
| 日志改异步(ch14)后 | 2.1µs | 7µs |

jitter 是全链路最坏值的卷积——优化必须打在「最大那块木板」上；一行 printf 毁掉整个实时性预算就是明证。

## 45.9 排故速查表

| 现象 | 根因候选 | 定位路径 |
|------|----------|----------|
| 偶发错过 deadline | DMA/中断突发挤占 + 未量化的 WCET | 全链路打点找最大阻塞元凶；WCET 重估加余量 |
| 加了新任务后老任务抖动 | 违反 RMS 单调性/利用率越限 | 重算 U；按周期重排优先级 |
| 互斥锁保护下仍有竞态 | 用了二值信号量(无继承)/锁粒度跨了共享变量 | 改 mutex；画出所有共享数据的锁序防死锁 |

## 45.10 部署注意事项

1. 上线前冻结「实时性预算表」：每个 deadline 分解到各级延迟预算并有测量数据背书；
2. 生产版本日志强制异步化，同步 printf 视为实时性事故源头；
3. 新增任何任务必须过一遍 U=ΣC/T 体检；存在 D<T 任务时改用响应时间分析 RTA 迭代 R=C+Σ⌈R/T⌉C 复核，不沿用 D=T 结论；
4. 多核系统不套用单核直觉——全局 vs 分区调度的干扰分析完全不同(ch50a)。

> **步骤**：① 列出你项目的全部周期任务 (C,T,D) 表；② 计算 U=ΣC/T 并对照 RMS 上限；③ 超 69% 则用时间轴仿真（纸笔或 python 脚本）验证真实可行性；④ 找出 D<T 的任务用 RTA 复核；⑤ 把结论写进项目实时性预算文档。

## 45.11 进阶话题

- **Cyclic Executive 的复兴**：极硬实时小系统里「时间触发表轮转」比 RTOS 更可预测（航空 DO-178 常见）——别把 RTOS 当信仰；
- **优先级天花板的手工实现**：拿锁瞬间 `vTaskPrioritySet` 到天花板、释放还原——FreeRTOS 无内置 PC 时可包一层封装；
- **多核调度理论变化**：全局 vs 分区调度的干扰分析完全不同，SMP 章(50a)再展开。

> [!warning]- ❓ FAQ
> **Q1：利用率 80% 是不是一定不可调度？** 不是。69%/82.8% 只是充分条件上界；具体任务集可能 U=0.95 仍可行，也可能 U=0.75 失败——唯一仲裁手段是时间轴仿真。
> **Q2：为什么 FreeRTOS 不内置 EDF？** 过载时 EDF 全体任务雪崩劣化且行为难预测；固定优先级过载时牺牲的只是低优先级任务，工业可控性更好。
