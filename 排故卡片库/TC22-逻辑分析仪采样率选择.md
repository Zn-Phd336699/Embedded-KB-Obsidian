# TC22 逻辑分析仪采样率选择

## 现象
同一批数据多次采集，协议解码结果不一致、边沿位置左右跳动几个采样点，窄毛刺干脆消失。典型触发：400kHz I²C 只给了 1MSa/s 采样率。

## 环境与适用范围
适用逻辑分析仪/sigrok-PulseView（fx2lafw、DSLogic 等）调试 UART/I²C/SPI/并口总线。模拟幅度类问题（振铃/过冲）应转示波器。

## 取证过程
1. 算需求：取信号最高翻转率（UART=波特率、SPI=SCK、I²C=时钟），按 ≥10× 规则定采样率下限。
2. 查现状：PulseView 设备属性里的 samplerate 与需求对照。
3. 提速复采：同一事件提高采样率重抓，解码趋于稳定、边沿不再抖动即欠采样实锤。
4. 查深度：存储深度 = 采样率 × 时长，确认窗口覆盖完整事务（如一整帧 Modbus）。
5. 毛刺排查：捕捉最窄脉宽需采样周期 < 脉宽/2，否则改用带毛刺触发/压缩模式的机型。

## 根因
采样把时间量化为 1/Fs 的格子。欠采样时边沿归属随机漂移 ±1 格，解码窗口判定随之抖动，表现为「时好时坏」的假象；Fs 翻倍则同样深度下窗口减半——这是采样率与存储深度的核心权衡。

## 修复方案
```bash
  # 经验下限：115200 UART ≥1MSa/s；400kHz I2C ≥4MSa/s；10MHz SPI ≥100MSa/s
  sigrok-cli -d dslogic -c samplerate=10M --time 200ms \
             --channels D0=TX,D1=SCL \
             -P uart:baudrate=115200,tx=TX -o uart_10M.sr
  # 深度不足时优先加触发条件截取关键窗口，而非盲目延长采集时间
```

## 预防措施
- 会话模板按总线类型固化最低采样率（UART 建议 ≥16× 波特率）
- 先设触发再采集，不做长时间盲采浪费深度
- 导出文件命名带上采样率，复核可追溯
- 关键信号就近接地，减少振铃造成的伪边沿
- 疑难问题双仪器交叉验证：LA 看时序，示波器看模拟品质
