## 8.1 目标架构：四层单向依赖

```text
┌───────────────────────────────────────────┐
│ App层    app_main.c app_task_xxx.c        │ 只 include 接口头(.h 无硬件痕迹)
├───────────────────────────────────────────┤
│ 服务层   sensor_svc.c storage_svc.c       │ 组合策略、缓存、调度
├───────────────────────────────────────────┤
│ 抽象接口 sensor_itf.h storage_itf.h       │ 纯虚函数表(struct of fn ptrs)
├───────────────────────────────────────────┤
│ 驱动层   drv_aht20.c drv_sd_spi.c         │ 实现接口，独占硬件细节
└───────────────────────────────────────────┘
依赖方向永远向下；上层禁止出现任何芯片型号字样——换 MCU 只改驱动层
```

腐化的根源是「到处 include」：App 直接调 HAL 后，换芯片/上模拟器/写单元测试全部瘫痪。

## 8.2 C 语言依赖倒置标准写法

```c
/* ---- sensor_itf.h：纯抽象 ---- */
typedef struct sensor_ops sensor_itf_t;
struct sensor_ops {
    int (*read)(sensor_itf_t *self, float *out);
    int (*selftest)(sensor_itf_t *self);
};
/* ---- drv_sht31.c：具体实现 ---- */
static int sht_read(sensor_itf_t *self, float *out) { /*...*/ }
const sensor_itf_t g_sensor_sht31 = { .read = sht_read, .selftest = NULL };
/* ---- app 层组装：board.c 是唯一知道型号的地方 ---- */
extern const sensor_itf_t g_sensor_sht31;
app_init((sensor_itf_t *)&g_sensor_sht31);
/* 测试时换成 mock 实现 —— ch09 单元测试的基础设施 */
```

## 8.3 高频模式三连

```c
/* ① 观察者：一对多事件广播（同步派发，注意回调耗时） */
typedef void (*obs_cb)(int topic, void *data, void *ctx);
int pub_publish(pubsub_t *ps, int topic, void *d) {
    for (obs_t *o = ps->subs[topic]; o; o = o->next) o->cb(topic, d, o->ctx);
    return 0;
}   /* 异步化变体：回调改成往各订阅者邮箱投递事件 */

/* ② 生产者消费者：ISR 生产 → 队列 → 工作任务消费 */
void UART_IRQHandler(void) { evt_t e = decode_isr(); xQueueSendFromISR(q_evt, &e, NULL); }
void worker_task(void *arg) {
    evt_t e;
    while (xQueueReceive(q_evt, &e, portMAX_DELAY) == pdTRUE) handle(&e);
}   /* 队列满策略要明确：丢弃+计数 or 覆盖最旧 */

/* ③ 代理/门面：给丑陋的 HAL 包一张好脸 */
int uart_write(uart_dev_t d, const void *buf, size_t len, int timeout_ms) {
    uart_lock(d);
    HAL_StatusTypeDef s = HAL_UART_Transmit(h[d], (uint8_t*)buf, len, to_ticks(timeout_ms));
    uart_unlock(d);
    return map_err(s);
}
```

## 8.4 init 表链接器自动收集（零手工注册）

```c
/* ① 注册宏：把初始化函数指针放进自定义段，段名带优先级字节 */
#define INIT_FN(prio, fn) \
    static const init_entry_t __init_##fn \
    __attribute__((used, section(".init_tab." #prio))) = { prio, fn }

INIT_FN(10, clock_init);      /* 各模块文件里各自一行 */
INIT_FN(20, sensor_init);

/* ② ld 脚本按段名排序收集（=按优先级排序），前后哨兵导出 __init_start/end
   ③ main 里遍历执行：for (p=__init_start; p<__init_end; p++) p->fn();
   —— 新增模块零改动 main：这就是 RT-Thread INIT_EXPORT 的原理 */
```

## 8.5 模块规范六条（贴墙上）

1. 每模块一个 `xxx.h`（对外契约）+ `xxx.c` + `xxx_internal.h`（私有）
2. 对外 API 一律返回错误码 int，0 成功负失败（errno 风格）
3. 禁止在 .h 里定义变量；全局状态封装成 get/set 或上下文指针
4. 初始化两段式：`xxx_early()`（时钟级）与 `xxx_open()`（业务级），顺序集中在 init 表
5. 所有延时走统一接口 `delay_ms()`，禁止裸循环（移植必炸）
6. 每模块自带 `#ifdef MODULE_SELFTEST` 自测入口（对接 ch09）

## 8.6 参数调试技巧

| 症状 | 测量手段 | 调什么 | 判据 |
|------|----------|--------|------|
| 改一处外设全工程报错 | `grep -rn "HAL_\|LL_" App/` | 补代理层收敛硬件访问 | grep 结果归零 |
| 观察者回调里死锁 | 文档标注回调执行环境 | 改投递异步事件 | 回调内无阻塞调用 |
| 初始化顺序随机成败 | map 查 init_tab 排序 | 链接器自动收集替代手工表 | 任意编译顺序结果一致 |

## 8.7 实测数据表：函数指针抽象的性能账单（F407 -O2）

| 调用形态 | 周期 | 相对直接调用 |
|----------|------|--------------|
| static 直接调用 | ~6 | 1.0x |
| 经结构体成员函数指针 | ~9 | 1.5x |
| 虚函数(vtable 查表) | ~11 | 1.8x |

结论：UART 事务(~ms 级)面前可忽略；仅 PID 内环等 µs 级路径需要开天窗直连。

## 8.8 排故速查表

| 现象 | 根因候选 | 定位路径 |
|------|----------|----------|
| 两模块互相 include 编译环 | 职责划分不清 | 抽第三个契约头文件放公共类型 |
| 绕过接口乱调 HAL | 无物理隔离无门禁 | 驱动 .h 不进 App include path + CI grep 门禁 |
| IAP 升级后驱动错配 | 新旧接口结构体不一致 | itf 首成员放 api_version 运行期校验 |

## 8.9 部署注意事项

1. 错误码分层设计：全局枚举 `-Exxx` + 模块内偏移段（如 ERR_MODBUS_BASE+n），日志打印自动还原模块名
2. 门禁的度：grep 规则太严会催生绕路 hack——保留白名单注释机制 `// ARCH-ALLOW:`，CI 解析豁免并要求评审确认
3. 物理隔离+CI 门禁+评审红线三保险；技术手段挡不住的靠流程兜底
4. ESP-IDF 的 esp_event 是异步观察者的工业实现；Zephyr device model 是 init 表+依赖注入的极致版

## 8.10 进阶话题

- 依赖注入的最小实现：「接口头 + 工厂函数返回 const 实现指针」三件套即可，关键是工厂只允许 board.c 一处调用
- 四层架构是第九篇所有项目(ch87~92)的骨架标准；观察者异步化即 ch48 的队列事件总线
- 《C Interfaces and Implementations》全书方法论；linux/kernel/irq/manage.c 的 ops 抽象是内核级参考
- 架构服务于可维护性：性能关键处开天窗直连是正常工程判断，不是妥协

> [!warning]- ❓ FAQ
> **Q1：函数指针表会不会太慢？**
> M4 上一次间接调用约 2~6 周期，相对毫秒级 IO 可忽略。真正的热点路径直连驱动即可。
> **Q2：怎么防止别人绕过接口乱调？**
> 物理隔离（include path）+ CI grep 门禁 + 代码评审红线，技术与流程双保险。
