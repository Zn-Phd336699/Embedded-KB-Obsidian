## 7.1 SPSC 无锁环形缓冲（串口/日志/DMA 标配）

```c
typedef struct {
    uint8_t *buf; uint32_t size;      /* size 必须 2 的幂 */
    volatile uint32_t head, tail;     /* 写者动 head，读者动 tail */
} ring_t;
#define RING_MASK(r,x) ((x) & ((r)->size - 1))

bool ring_put(ring_t *r, uint8_t b) {          /* 仅生产者调用 */
    uint32_t next = RING_MASK(r, r->head + 1);
    if (next == r->tail) return false;         /* 满：留一格区分满/空 */
    r->buf[RING_MASK(r, r->head)] = b;
    __DMB();                                   /* 先写数据后发布 head（内存序） */
    r->head = next;
    return true;
}
bool ring_get(ring_t *r, uint8_t *b) {         /* 仅消费者调用 */
    if (r->tail == r->head) return false;
    *b = r->buf[RING_MASK(r, r->tail)];
    __DMB();
    r->tail = RING_MASK(r, r->tail + 1);
    return true;
}
```

> [!warning] 安全边界
> 只支持 **1写1读**！多生产者需要关中断或 CAS——别硬撑无锁。多写场景先考虑「每生产者私有 ring + 消费者轮询聚合」，把并发问题降维成 SPSC 组合。

## 7.2 三种缓冲结构选型几何

| 结构 | 容量效率 | 并发模型 | 适用信号 |
|------|----------|----------|----------|
| SPSC 环形(留一格) | N-1/N | 1写1读无锁 | 日志/串口字节流 ★默认 |
| 环形+count原子 | N/N 满 | 需 LDREX 原子加减 | 满载不丢场景 |
| DMA 写指针推导 | N/N | 硬件维护零成本 | DMA 循环接收 ★最优 |
| 乒乓双缓冲 | 50% | 整块交接天然同步 | 音频/DMA 大块流 |

DMA 推导法核心一行：`uint32_t wpos = size - __HAL_DMA_GET_COUNTER(hdma);`——注意 NDTR 单位是「数据项」不是字节。第28章串口不定长接收用的正是它。

## 7.3 侵入式链表 + container_of

```c
typedef struct list_node { struct list_node *prev, *next; } list_node_t;
void list_add_tail(list_node_t *head, list_node_t *n) {
    n->next = head; n->prev = head->prev;
    head->prev->next = n; head->prev = n;
}
void list_del(list_node_t *n) { n->prev->next = n->next; n->next->prev = n->prev; }
#define list_entry(ptr, type, memb) container_of(ptr, type, memb)

/* 业务结构体内嵌节点——零拷贝、节点生命周期=对象生命周期 */
typedef struct task { int prio; char name[8]; list_node_t node; } task_t;
list_for_each(p, &g_ready) {
    task_t *t = list_entry(p, task_t, node);   /* 从节点还原宿主 */
}
```

遍历中删除必须用 `list_for_each_safe` 版本宏——否则野指针。

## 7.4 静态对象池（malloc 替代品）

```c
typedef struct {
    void *mem; uint32_t blk_size, cnt;
    list_node_t free_list;            /* 空闲块穿成链 */
} pool_t;

void *pool_alloc(pool_t *p) {         /* O(1)；RTOS 版内部加互斥 */
    if (list_empty(&p->free_list)) return NULL;
    list_node_t *n = p->free_list.next;
    list_del(n);
    return n;
}
```

优点：分配 O(1)、无碎片、泄漏可数（剩余块数）；代价：类型固定、需预估峰值。块尺寸须向上取整到 `alignof(max_align_t)`，池基址 aligned(8)。

## 7.5 表驱动状态机

```c
typedef enum { EV_BTN, EV_TICK, EV_RX } evt_t;
typedef enum { ST_IDLE, ST_RUN, ST_ERR } st_t;
typedef st_t (*handler_t)(evt_t e);

static st_t on_idle(evt_t e) { if (e==EV_BTN) return ST_RUN; return ST_IDLE; }
static st_t on_run (evt_t e) { if (e==EV_TICK) return ST_IDLE;
                               if (e==EV_RX && !valid()) return ST_ERR; return ST_RUN; }
static st_t on_err (evt_t e) { if (e==EV_BTN) return ST_IDLE; return ST_ERR; }

static const handler_t tab[] = { [ST_IDLE]=on_idle, [ST_RUN]=on_run, [ST_ERR]=on_err };
st_t fsm_step(st_t cur, evt_t e) {
    st_t nxt = tab[cur](e);
    if (nxt != cur) log_state(cur, nxt);   /* 状态迁移留痕——排障神器 */
    return nxt;
}
```

每个状态必须有 default 分支转 ERR/自恢复态——「事件丢失导致卡死」九成是漏了兜底边。进阶形态：层次状态机（入口/出口动作+嵌套）参考 QP/QM 框架。

## 7.6 参数调试技巧

| 症状 | 测量手段 | 调什么 | 判据 |
|------|----------|--------|------|
| 环形缓冲偶发丢字节 | 确认「谁写 head 谁唯一」 | ISR 与主循环改双缓冲或队列 | 多轮压测零丢失 |
| 对象池返回坏指针 | 打印块尺寸与对齐 | sz 取整 alignof(max_align_t) | 全部指针 8 字节对齐 |
| 状态机卡死某状态 | log_state 全量留痕回放 | 补 default 兜底迁移 | 异常事件后能自恢复 |

## 7.7 实测数据表：容器操作真实周期（F407@168MHz -O2）

| 操作 | 周期 | 备注 |
|------|------|------|
| ring_put 单字节 | ~11 cycles | 含满判断与写回 |
| pool_alloc(O(1)链表) | ~14 cycles | vs malloc ~200+ 且不确定 |
| fsm_step 表驱动 | ~16 cycles | 迁移日志钩子关闭时 |
| wheel_tick 单级轮 | O(空链表)=8 | k 个到期时 O(k)，k 通常 ≤2 |

## 7.8 排故速查表

| 现象 | 根因候选 | 定位路径 |
|------|----------|----------|
| 缓冲满/空判定错乱 | count 更新缺原子性 / 索引未取模 | 断言 head-tail 恒在 [0,size) 区间 |
| 时间轮定时器不触发 | 未处理同 tick 重插 / 轮径不够 | 两级轮扩展；到期降级下插逻辑单测 |
| 链表遍历中删除野指针 | 没用 _safe 版本宏 | Code Review 清单加入此条 |

## 7.9 部署注意事项

1. 运行期 MCU 固件坚持静态/池化；动态内存只允许初始化阶段一次性配置
2. FSM 与 RTOS 任务配合：每任务内部跑一个 FSM，从队列取事件喂 fsm_step——跨任务协作变成「发事件」而非「抢变量」（Actor 模型嵌入式落地）
3. 时间轮替代满天飞的软定时器；长延时用两级轮（低 8 位毫秒轮+高 8 位秒轮），Linux 内核 htimer 同思想
4. lwIP mempool、FreeRTOS timers.c 都是本章思想的工业级参考实现

## 7.10 进阶话题

- 侵入式 vs 非侵入式：节点内嵌省一次分配且生命周期清晰；代价是类型耦合。内核风格=侵入式，业务临时集合=数组即可
- 属性测试思想：对纯函数用随机生成+不变量断言自动找边界（如编码再解码必还原）
- QP/C 框架文档是 HSM 的进阶读物；《C Interfaces and Implementations》第5章是原子池设计参考
- linux/lib/kfifo 是 SPSC 环形的官方参考实现（含内存序注释）

> [!warning]- ❓ FAQ
> **Q1：什么时候才允许用动态内存？**
> 初始化阶段一次性配置（解析 JSON 配置后立即释放）、Linux 应用层随意；运行期固件坚持静态/池化。
> **Q2：SPSC 为什么留一格而不加计数器？**
> 留一格让读写指针各自独立更新即天然区分满/空；带 count 能存满 size 字节但 count 更新需要原子性，M3+ 可用 LDREX 实现。
