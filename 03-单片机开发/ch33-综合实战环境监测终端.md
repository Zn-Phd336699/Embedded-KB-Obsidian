## 33.3 任务划分与优先级（RTOS 版）

| 任务 | 周期/触发 | 优先级 | 栈(B) | 说明 |
|------|-----------|--------|-------|------|
| sensor_task | 1s 定时 | 4 | 512 | 读 SHT31/PMS，滤波入环形缓冲 |
| gui_task | LVGL 30Hz tick | 5 | 2048 | LvglHandler + 曲线刷新 |
| net_task | 队列驱动 | 6 | 4096 | MQTT 收发 + JSON 组包 |
| alert_task | 事件驱动 | 7 | 256 | 阈值判断与声光输出（状态机见 [[ch07-嵌入式数据结构与算法]]） |
| log_task | 持续 | 2 | 512 | [[ch14-日志系统设计RTT与远程回传]] 异步日志搬运工 |

```c
/* 数据流：全部经队列/通知传递，无共享全局变量竞态面 */
sensor_task --xQueueSend(data_evt)--> net_task      /* 上报 */
           --xTaskNotify(chart_hdl, val)--> gui_task /* 刷新 */
/* 时序预算：采集 <15ms（SHT31 单次测量 8.5ms）；MQTT 发布 <300ms；
   LVGL 单帧 <25ms（SPI@40MHz 320x240）—— 三项全部留有 2 倍裕量 */
```

## 33.4 LVGL 移植五步

1. **lv_conf.h**：使能 `LV_COLOR_DEPTH 16`、字体子集，mem_size 用静态数组；
2. **port_disp**：flush_cb 里 DMA 推送行缓冲 → `lv_disp_flush_ready()`；
3. **port_indev**：触摸 IC（XPT2046/FT6336）读取封装进 read_cb；
4. **tick 与心跳**：SysTick 中断里 `lv_tick_inc(1)`；gui_task 循环 `lv_timer_handler()` + `vTaskDelay(5)`；
5. **性能三开关**：直接模式/双缓冲取舍、DMA2D 加速取舍、`LV_USE_PERF_MONITOR` 看 FPS/CPU——验收锚点：屏幕出内容（哪怕乱码）→ FPS≥30 @ 目标分辨率 → 业务数据变化 UI 自动刷新。

## 33.5 MQTT 业务层 JSON 协议

```json
// 上行 topic: dev/{sn}/telemetry
{"t":1724470000,"temp":26.4,"rh":58.2,"pm25":35,"rssi":-62}
// 下行 topic: dev/{sn}/cmd （QoS1 + retained=false）
{"id":42,"act":"set_threshold","pm25":75}
```

设计要点：cmd 带 `id` 幂等去重；断网期间本地缓存最近 100 条补传（带 seq）且队列必须设上限防撑爆。云协议本体深究见 [[ch80a-MQTT-CoAP云协议本体与实现]]。

## 33.9 排故速查表

| 现象 | 根因候选 | 定位路径 |
|------|----------|----------|
| 曲线刷新整机卡顿 | 曲线每点重绘整图/SPI 未走 DMA | lv_chart 只推新点(set_next_value)+曲线区降 2Hz；确认 DMA 且 flush_cb 不忙等 |
| broker 连上但发布丢失 | QoS0 不保证送达 | 改 QoS1+seq 去重；断网缓存队列设上限防撑爆 |
| SHT31 偶发读数全 F | I2C 总线干扰或上拉不足 | 示波器看边沿([[ch18-示波器实战]])；CRC 失败重试+连续失败告警；总线卡死走 [[ch76-I2C协议与排障时钟拉伸总线锁死多主机]] 解锁流程 |

## 33.10 部署与交付：72h 老化清单（交付前必过五关）

1. **72 小时老化**：内存水位无增长、无重启、上报成功率 ≥99.5%；
2. **断网恢复**：拔网线 10 分钟插回，缓存补传且不重复；
3. **异常注入**：SHT31 拔除→UI 显示"--"且告警不崩溃；PM 乱码帧→解析器自愈；
4. **功耗实测**（电池版）：休眠均值 vs 计算值偏差 <20%；
5. **OTA 演练**：升级中断电→回滚成功→再次升级成功。

> [!example]- 🧪 动手实验 L33-1：故障注入生存测试（30 分钟）
> **步骤**：运行完整固件 → 运行中拔掉 SHT31 观察界面与告警 → 重新插入观察恢复 → 再向 PMS 串口灌入乱码字节流。
> **验收**：拔除期间 UI 显示"--"、声光告警、系统无重启；乱码帧被丢弃且解析器自愈；重新接入后 3s 内恢复有效读数并继续上报。

> [!warning]- ❓ FAQ
> **Q1：LVGL 和业务逻辑抢 CPU 卡顿？** 渲染放最高可用优先级但每帧主动让步；SPI 时钟拉满并用 DMA 行推送；降低非关键刷新率（曲线区 5Hz 足够）。终极方案是 F407 用 LTDC+双层显存直接模式。
> **Q2：PM2.5 改成 I2C 型号要改多少？分层是否合格如何验证？** 仅 sensor_task 的传感器适配层要改，gui/net/alert 零改动——这就是检验分层的试金石。
