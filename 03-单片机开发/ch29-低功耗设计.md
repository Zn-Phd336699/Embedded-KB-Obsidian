# 第29章 低功耗设计：模式选型、RTC 唤醒与功耗测量方法

> [!info] 导航
> ⏱ 40min | ★★★★☆ | 前置 [[ch28-串口工程化IDLE-DMA-RS485]] | → [[ch29a-电源异常与掉电保护]]

电池设备的生命线：从 168MHz 全速的几十 mA 到 Standby 的 2µA，每一档都有代价与玩法。

## 🎯 学习目标
- [ ] 默写 F407 各低功耗模式的进入/退出/唤醒源矩阵
- [ ] 完成 RTC 周期唤醒「采集→上报→回睡」闭环并核算平均电流与续航
- [ ] 掌握 µA级测量三板斧与逐项归因清单，实现 NoInit 段冷热启动判别

## 29.1 模式矩阵：每一档都有代价

| 模式 | 关什么 | 典型电流 | 唤醒源 | RAM/寄存器 |
|------|--------|----------|--------|------------|
| Sleep | CPU 时钟 | ~mA 级 | 任一中断 | 全保留 |
| Stop | 1.2V 域全部时钟 | ~百µA | EXTI 边沿 / RTC | SRAM 保留，HSI/HSE 丢 |
| Standby | 几乎全掉电 | **~2.4µA** | WKUP 引脚 / RTC / IWDG | SRAM 丢失，等效复位 |
| VBAT | 仅 RTC+备份域 | nA 级 | - | 备份寄存器 20 个 |

## 29.2 关键代码：Stop 模式进出模板

```c
void enter_stop(void){
    gpio_all_quiesce();          /* ① 进之前钉死所有IO：浮空引脚会振荡耗电(ch23.5) */
    /* ② 关不用的外设时钟 RCC->APBxENR；ADC 等模拟块显式关闭 */
    HAL_RTC_SetAlarm_IT(&hrtc,&alarm,RTC_FORMAT_BIN); /* ③ 配唤醒源：RTC闹钟 */
    __HAL_PWR_CLEAR_FLAG(PWR_FLAG_WU);                /*    清唤醒标志防立即退出 */
    HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON,PWR_STOPENTRY_WFI);
    SystemClock_Config_FromStop();/* ④ 唤醒后系统时钟回到 HSI 8M！必须重配 PLL */
}
```

经典坑：唤醒后串口波特率全乱——就是忘了重配时钟，串口还在跑旧 BRR 值。深睡前统一走「等待 UART TC 标志 → 再睡」包装函数，杜绝发送中被冻结截尾的半截帧。

## 29.3 周期采集上报完整闭环

```text
┌────────┐ RTC闹钟 ┌─────────┐ 上报 ┌────────┐
│Standby │───────▶│ 快速采集 │────▶│ 发送   │──▶ 回Standby
│ 2µA    │ 每10min│ ~50ms   │      │ ~2s    │
└────────┘        └─────────┘      └────────┘
平均电流 = (2µA×600s + 8mA×0.05s + 80mA×2s) / 602s ≈ 0.29mA
2000mAh 电池理论续航 ≈ 9 个月 —— 链路预算式的设计思维！
优化抓手排序：无线休眠深度 > 上报频率 > 传感器上电策略 > MCU模式
```

## 29.4 功耗测量三板斧

1. **µA 表串联法**：稳态值直接读；缺点是动态毛刺看不到平均真值。
2. **采样电阻+示波器**：0.1Ω~1Ω 串入电源，差分探头看压降换算电流——能看见 WiFi burst 的 mA 级尖峰细节（联动 [[ch18-示波器实战]]）。
3. **功耗分析仪（Joulescope / Nordic PPK2）**：µA~A 动态范围自动量程，按事件分段统计能量占比，直接告诉你「谁偷走了电池」。

## 29.5 逐项归因清单

整机待机 500µA 而目标 50µA？按序排查：① LED/指示灯电路 ② 上拉电阻网络持续导通 ③ 传感器供电未切断（加 PMOS 高边开关）④ DC-DC 静态电流选型 ⑤ GPIO 电平与外围冲突 ⑥ 调试口 ST-Link 还挂着 ⑦ 未进入预期模式（唤醒标志没清导致立即退出）。经验分布：前四项占九成。

## 29.6 关键代码：冷热启动判别模块（NoInit 段法）

```c
/* boot_reason.c —— Standby/复位后判断「我是谁」 */
__attribute__((section(".noinit"))) uint32_t magic;
#define MAGIC_WARM 0xB007CAFE
bool is_warm_boot(void){
    bool warm = (magic==MAGIC_WARM) &&
                (RCC->CSR & RCC_CSR_IWDGRSTF || PWR->CSR & PWR_CSR_SBF);
    magic = MAGIC_WARM;                 /* 首次运行后打标 */
    __HAL_RCC_CLEAR_RESET_FLAGS();
    return warm;
}
```

配套改动两处：链接脚本增加 `.noinit (NOLOAD): { *(.noinit*) } > RAM`；更稳的双保险是把关键状态同时写一份备份寄存器（RTC_BKP），魔数+校验和都通过才敢恢复现场。用途：恢复现场状态机、跳过自检加速热启动（联动 [[ch56-启动流程深度剖析systemd提速]] 思想）。

## 29.7 参数调试技巧

| 症状 | 测量手段 | 调什么 | 判据 |
|------|----------|--------|------|
| 待机电流远超手册 Stop 规格 | µA 表串联读稳态 | 钉死浮空脚、关未用外设时钟、拔调试器 | 与规格差 <2 倍 |
| RTC 日漂移明显 | 与标准时钟对时记录日差 | LSE 负载电容匹配+RTC 校准寄存器 | 补偿到 ±ppm 级 |
| 睡下去立刻被唤醒 | 逻辑分析仪抓 EXTI 电平 | 清 WUF 后再 WFI、悬空脚上下拉 | WFI 后保持睡眠 ≥ 设定周期 |

## 29.9 排故速查表

| 现象 | 根因候选 | 定位路径 |
|------|----------|----------|
| 进了 Stop 立刻被唤醒 | EXTI 悬空引脚抖动触发 / WUF 未清 | 上拉/下拉钉死悬空脚；清 WU 标志顺序核对 |
| Standby 唤醒后变量丢失 | Standby 本质是复位，SRAM 不保 | 关键状态存备份寄存器(RTC_BKP)或 NoInit 段+魔法数判断冷热启动 |
| 实测比手册大十倍 | 外围电路漏电占主导 | 断开外围逐一复测；关注分压电阻网络与 TVS 管 |
| RTC 走时不准 | LSE 32.768kHz 负载电容失配 | VNA 或示波器低容探针校频；校准寄存器补偿 ppm |

## 29.10 部署注意事项

1. BOR 复位阈值必须高于 Flash 写操作最低电压，产品级显式配置 option bytes 而非默认（详见 [[ch29a-电源异常与掉电保护]]）。
2. 新项目开工第一天画「唤醒源矩阵表」贴墙：每个 EXTI 线映射哪些脚、各模式可用什么唤醒。
3. 量产测试必须包含「拔调试器后的真实待机电流」项——整改瀑布证明软件只贡献最后一小截，低功耗是电路设计问题。
4. RTOS 场景优先用 tickless idle 让内核统一管理睡眠时机（[[ch50-FreeRTOS中断管理与Tickless低功耗]]）。

> **步骤**：① 万用表 µA 档串入电源，进入 Stop 记录基线；② 按「断开外围→逐组钉电平→逐外设关时钟」顺序每步记录电流；③ 定位最大漏电项并修复；④ 用采样电阻+示波器复测一次动态唤醒瞬间电流峰。

## 29.11 进阶话题

- **LSE 校准的工程做法**：用 HSE 精度做参考测 LSE 实际频率，写 RTC 校准寄存器（±ppm 级）——水表类「十年误差<分钟」需求的必答题。
- **深睡前的 UART 收尾**：Stop 冻结波特率时钟，统一走「TC 等待→睡」包装函数。
- **ESP32 对照架构**：deep sleep 定时唤醒 + ULP 协处理器预筛数据的同等设计见 [[ch32-ESP32外设与WiFi-BLE上手]]。

> [!warning]- ❓ FAQ
> **Q1：为什么唤醒后外设行为全乱？** A：Stop 退出后系统时钟默认回到 HSI 8MHz，所有基于旧时钟频率的外设配置（波特率 BRR、定时器分频）全部失效，第一步必须是重配 PLL 并恢复外设时钟。
> **Q2：Standby 和 Stop 怎么选？** A：需要秒级快速恢复现场且保 SRAM 选 Stop；可以接受「醒来即复位」换 2µA 级超低功耗选 Standby，配合备份寄存器/NoInit 保存关键状态。

> 2. 设计冷启动/热启动识别方案：备份寄存器魔数 + RAM 校验和双重保险。
> 3. 为 ESP32-S3 对照设计同等功能：deep sleep 定时唤醒 + ULP 协处理器预筛数据的架构。
