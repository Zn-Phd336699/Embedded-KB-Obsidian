# 第15章 内存问题排查三板斧：Canary / 统计 / Sanitizer

> [!info] 导航
> ⏱ 40min | ★★★☆☆ | 前置 [[ch14-日志系统设计RTT与远程回传]] | → [[ch16-perf-ftrace-strace性能剖析]]

内存类 Bug 占嵌入式缺陷一半以上。本章给出从 MCU 到 Linux 的完整武器库：栈溢出三检测法、xmalloc 堆统计器、主机侧 ASan/Valgrind，以及无 MMU 芯片上的等价替代。

## 🎯 学习目标
- [ ] 掌握栈溢出三检测法：水位线、MPU 哨兵页、RTOS 魔数自检的原理与开销差异
- [ ] 实现 xmalloc 统计器：cur/peak/fail/bad_free 与按行号聚类的泄漏 TOP5
- [ ] 理解 ASan redzone+影子内存+quarantine 的抓越界机制及其代价

## 15.1 核心概念：栈溢出检测三法

| 方法 | 原理 | 开销 | 时机 |
|------|------|------|------|
| 水位线法 | 启动涂色（[[ch06-链接器与内存布局]] stack_paint），巡检统计最深用量 | 零运行开销 | 持续观测，余量<20% 即告警 |
| MPU 哨兵页 | 栈底一页设 no-access，溢出立即 MemManage Fault | 一次配置 | 开发期抓现行；fault handler 打印任务名 |
| RTOS 自检 | FreeRTOS configCHECK_FOR_STACK_OVERFLOW=2：切换时查栈底魔数+水位 | 极小 | 量产也建议开 level 1（仅魔数） |

## 15.2 平台替代矩阵：没有 ASan 的 MCU 世界怎么办

| 缺陷类 | 主机 ASan 抓法 | MCU 等价物 |
|--------|----------------|------------|
| 堆越界/UAF | redzone + quarantine | xmalloc 魔数 + 池边界哨兵 |
| 栈溢出 | -fstack-clash-protection | MPU 哨兵页 + 水位线（[[ch21-Cortex-M架构精讲]]） |
| 未初始化读 | MSan（Linux only） | 启动涂色 + 静态扫描 -Wmaybe-uninitialized |
| DMA 一致性 | N/A | Invalidate/Clean 纪律 + noncacheable 区（[[ch26-DMA与Cache一致性]]） |

总原则：业务逻辑全部下沉到主机可测层，MCU 只留薄薄的硬件胶水——[[ch08-分层架构与设计模式]] 红利的兑现处。Linux 板直接用交叉编译版 ASan/LSan，开销约 2 倍（典型值），测试环境完全可接受。

## 15.3 关键代码：xmalloc 统计器与主机侧 Sanitizer

包一层 malloc：统计 + 泄漏追踪 + 双重释放检测。周期任务打印统计量与存活分配按 line 聚类 TOP5——泄漏元凶一目了然。

```c
typedef struct hdr { uint32_t magic,size,line; struct hdr*next; } hdr_t;
static hdr_t *g_allocs; static heap_stat_t g_stat;
void *xmalloc(size_t sz,int line){
    hdr_t*h = malloc(sizeof(hdr_t)+sz);   /* 生产版可换 pvPortMalloc */
    if(!h){ g_stat.fail++; return NULL; }
    h->magic=0xDEADC0DE; h->size=sz; h->line=line; h->next=g_allocs; g_allocs=h;
    g_stat.cur_bytes+=sz; if(g_stat.cur_bytes>g_stat.peak) g_stat.peak=g_stat.cur_bytes;
    return h+1;
}
void xfree(void*p,int line){
    if(!p) return;
    hdr_t*h=(hdr_t*)p-1;
    if(h->magic!=0xDEADC0DE){ g_stat.bad_free++; return; } /* 双重释放/野指针现行 */
    h->magic=0;
    for(hdr_t**it=&g_allocs;*it;it=&(*it)->next)
        if(*it==h){ *it=h->next; break; }
    free(h);
}
```

主机侧重炮——ASan 编译期插桩，Valgrind 无需重编但慢约 20 倍：

```bash
gcc -fsanitize=address -fno-omit-frame-pointer -g test_x.c x.c -o t && ./t
  # ==123==ERROR: AddressSanitizer: heap-buffer-overflow on address ...
  # WRITE of size 4 at ... by thread T0:
  #     #0 process_frame src/dsp.c:57        ← 直接给到行号！
gcc -fsanitize=undefined -fno-sanitize-recover=all ...   # UBSan：有符号溢出/错位/空引用
valgrind --leak-check=full --track-origins=yes ./unit_test
```

redzone 抓越界的原理：

```text
编译期：每次访存前插入影子内存检查 shadow=(addr>>3)+offset;
        若 shadow_byte!=0 且 addr&7>=k 则 __asan_report()
运行期：堆块两侧垫 redzone(默认16B+)标记为「毒」；
        free 后整块投毒 + quarantine 隔离队列延迟复用 → UAF 必被抓
栈变量同样插帧内毒区 + 函数退出重毒。代价：内存 ×2~3、CPU ×2 —— 只在主机/测试构建开启。
```

## 15.4 参数调试技巧

| 症状 | 测量手段 | 调什么 | 判据 |
|------|----------|--------|------|
| 变量隔几小时被改 | GDB watchpoint（[[ch12-GDB深度实战]]） | 相邻数组加哨兵填充 | watchpoint 命中即现行 |
| 运行变卡直至失败 | peak 曲线 + 碎片率巡检 | 固定尺寸请求改池化（[[ch49-FreeRTOS内存管理heap与栈检测]]） | frag<25% 且峰值平稳 |
| DMA 收到旧数据 | Invalidate 后复测 | 核对缓冲区缓存属性 | 关 D-Cache 复现消失→确认伪损坏 |

## 15.5 实测数据表：检测手段的开销量级

| 手段 | 内存开销 | CPU 开销 | 适用环境 |
|------|----------|----------|----------|
| ASan | ×2~3 | ×2 | 主机/测试构建 |
| Valgrind Memcheck | 数倍 | 慢 ~20 倍 | 主机离线复测 |
| xmalloc 头部 | 每块 +16B | O(n) 链遍历 | MCU 全程可跑 |
| 水位线涂色 | 栈区本身 | 零（仅巡检时） | MCU 全程可跑 |

## 15.6 排故速查表

| 现象 | 根因候选 | 定位路径 |
|------|----------|----------|
| 某变量隔几小时被改 | 相邻数组溢出/野指针/DMA 越界 | GDB watchpoint；哨兵填充；ASan 主机复测同逻辑 |
| 长时间运行变卡直至失败 | 内存碎片化或泄漏累积 | xmalloc 看 peak 曲线；按 line 聚类；碎片率=1-最大空闲块/总空闲 |
| 数据「偶尔旧一帧」 | Cache 未失效（M7/A核），非真踩内存 | Invalidate 后复测；核对缓冲区域缓存属性 |
| free 后偶发崩溃 | 双重释放/use-after-free | bad_free 计数器；ASan 必抓；池化管理根治 |
| 栈相关随机 HardFault | 任务栈不足/ISR 嵌套超预算 | 水位线报表；configCHECK=2；-fstack-usage 最坏链分析 |

## 15.7 部署注意事项

1. 业务层代码在主机跑全套 Sanitizer 单测（[[ch09-MISRA-C与单元测试]] CI 一环），MCU 上只留硬件胶水。
2. 量产固件建议保留 `configCHECK_FOR_STACK_OVERFLOW=1`（仅魔数），开销极小。
3. 「每周内存健康报告」盯三个指标：碎片率、ever_min 余量、bad_free 计数。
4. MCU 池化后把刚释放块延迟几个 tick 再入自由链（quarantine 思想），低成本抓多数 UAF；GCC `-fsanitize=address` 在部分 ARM 工具链仍属实验性——关注但别押注。

## 15.8 进阶话题
- **碎片率健康阈值**：frag>40% 且 ever_min<20% 双黄灯就该重构分配模式——固定尺寸请求改池化立竿见影
- **Cache 伪损坏诊断三步**：关 D-Cache 复现消失 → 开 noncacheable 区验证 → 最后才补屏障代码，顺序反了浪费一天
- **泄漏归因单位**：按「调用点行号」聚合比按大小聚合更有行动价值——修复永远发生在代码里而不是数字里

> [!warning]- ❓ FAQ
> **Q1：为什么 ASan 的 redzone 不能直接搬到无 MMU 的 MCU？** 影子内存需要映射与插桩基础设施，且内存 ×2~3 在 MCU 上不可承受；粒度只能退化为哨兵魔数。
> **Q2：MPU 哨兵页触发后 fault handler 该打印什么？** 任务名、栈基址/水位、触发访问地址——足够定位哪条任务栈顶穿了保护页。
